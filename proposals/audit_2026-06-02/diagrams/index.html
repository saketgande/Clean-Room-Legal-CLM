CONTEXT ① How the system is put together

Before we look at problems, here's the system as it stands: a Next.js frontend, a FastAPI backend with 22 domain routers and a dedicated AI layer, a Postgres database, Redis, Celery workers, and four external APIs.

CRITICAL ② The AI chat keeps writing to a closed database connection

Finding F-01. The streamed reply outlives the request that started it. Database writes after the dependency closes cause intermittent, hard-to-debug failures.

CRITICAL ③ Approval-token endpoint leaks information and has no rate limit

Finding F-02. Different error codes for "fake", "expired", "used" tell an attacker which tokens were real. No rate limit means unlimited guessing.

CRITICAL ④ Admin queries can leak another company's contracts

Finding F-03. The "accessible contract filter" returns TRUE for admins, so any query that joins contracts without its own org filter can surface other tenants' rows.

CRITICAL ⑤ AI feature flags exist but the code never checks them

Finding F-04. Toggling a feature off in the admin UI literally does nothing. There's no kill-switch for a misbehaving AI tool.

PLAN ⑥ The 4-sprint plan to fix it all

~8 weeks total. Sprint 1 stops the bleeding. Sprint 2 makes errors visible. Sprint 3 preps for 10× scale. Sprint 4 cleans up.
