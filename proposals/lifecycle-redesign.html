● Now — fixed wizard

  • One linear chain of “Advance →” buttons
  • User manually clicks each stage forward
  • Stage = a position you push through
  • No board; one contract at a time
  • Approvals are a single step

● Proposed — living pipeline

  • Kanban board: drag cards between stages
  • Work completing moves the contract automatically
  • Stage = a status that knows its own exit gate
  • Whole portfolio visible; WIP per column
  • Parallel + sequential approval tracks
All three reuse data your backend already returns — contracts_by_stage (board columns), allowed_transitions (legal drops), approvals (the gate). Nothing here is wired; it's a visual proposal.
