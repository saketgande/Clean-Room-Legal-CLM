## Format

`- [ ] T00N [P] (agent) Description — dependsOn: T00X, T00Y — files: path/one, path/two`

- `[P]` = may run in parallel with other `[P]` tasks in the same wave (no shared files).
- `dependsOn: —` means no dependencies (wave 1).
- Every task maps to requirement(s) from spec.md, noted as `(FR-N)`.
- Two tasks that touch the same file must never carry `[P]` together — watch the
  shared hotspots: `backend/app/models.py`, `backend/app/jobs/tasks.py`,
  `frontend/src/lib/endpoints.ts`, `frontend/src/lib/types.ts`,
  `frontend/src/components/ui.tsx`.
- Migration tasks never run in parallel with each other (single Alembic head).

**Money rule for every task:** no task makes a paid call. Every test runs with `MOCK_*` on, as CI
does; findings, failures and cost-cap cases come from the `_FakeReview` monkeypatch and the patched
`reducto_client.extract_text` described in plan.md "Test strategy". Jobs are run in tests with
`asyncio.run(checks.run_check_job(db, job))`, never through Celery.

**Contract rule:** every task codes against plan.md's Interface freeze (API table, JSON shapes, exact
error messages, audit actions, DB schema, TS interfaces, frozen `checks.py` signatures). A task that
needs to change any of those stops with `blocked` and says why; it does not improvise.

**Done means:** the task's own tests pass, plus `ruff check .` (backend tasks), `alembic upgrade head`
(migration tasks), and `npm run typecheck` + `npm run test` (frontend tasks; never `npm run lint`).
